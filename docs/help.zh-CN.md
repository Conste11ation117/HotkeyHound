# HotkeyHound 帮助（简体中文）

HotkeyHound 是一个 Windows 全局快捷键冲突排查工具。它帮你看清楚：**哪些热键被占用了、被谁占用了、
为什么你按下去的键没有反应、以及哪些键是空闲的可放心使用。**

它只读取和探测，不修改任何配置、不写注册表、不结束任何进程。

---

## 1. 这个工具解决什么问题

日常里最烦的几种情况，HotkeyHound 都有对应手段：

- 想给某个软件设一个全局热键，却提示「快捷键已被占用」，但不知道被谁占了。
- 某个键按下去毫无反应，说不清是被别的软件抢了，还是被某个钩子吞了。
- 换电脑 / 装了新软件后，一堆原来的快捷键行为变了，想排查是哪一个软件造成的。
- 想知道某一组键（例如 `Ctrl+Alt+F13`）到底是不是空着，能不能拿来用。

它由四个引擎组成，分别回答上面不同的问题。

---

## 2. 四个引擎

### 引擎 A —— 占用扫描（只读，不需要管理员）

**做什么**：对每一种「修饰键组合 × 按键」（约 1650 个组合）调用 Win32 `RegisterHotKey` 试探：
成功就立刻 `UnregisterHotKey` 注销，记为**空闲**；失败且错误码为 1409
（`ERROR_HOTKEY_ALREADY_REGISTERED`）记为**已占用**。

**怎么用**：图形界面「扫描总览」页点「开始扫描」，或命令行

```
HotkeyHound.exe --scan --report 我的报告.html
```

**风险**：几乎为零。扫描过程不改设置、不写注册表，注册动作在同一瞬间被撤销。

### 引擎 B —— 按键归属（需要安装钩子；建议管理员）

**做什么**：装一个全局消息钩子（`WH_GETMESSAGE`，由一个原生 DLL 实现），拦截
`WM_HOTKEY` 消息。当你按下某个全局热键时，持有它的进程会收到这条消息，钩子顺手把
「持有者进程 PID + 组合键」报回来，于是你就知道**这个热键究竟是谁的**。

**怎么用**：图形界面「按键归属」页点「开始监听」，然后按下想排查的热键；或命令行

```
HotkeyHound.exe --listen --seconds 30
```

**风险**：这一项会安装全局钩子，且会把原生 DLL 注入到当前会话的每个进程。因此：

- **只有你显式点「开始监听」时才安装**，点「停止监听」立刻卸载；
- 程序加载界面时**不会**安装任何钩子；
- 请尽量以管理员身份运行，否则看不到提权进程（例如以管理员运行的 PowerToys）。

### 引擎 C —— 钩子窃取检测（需要安装钩子）

**做什么**：装一个低层键盘钩子 `WH_KEYBOARD_LL`，观察按键是否到达系统。结合引擎 A 的占用表与
引擎 B 的归属报告，给出四分支结论：

| 结论 | 含义 |
|---|---|
| 正常送达 | 按键到达系统，并且收到了明确的归属报告 |
| 疑似被钩子截胡 | 按键到了系统，但持有者没收到命令——被某个钩子拦了 |
| 被上层钩子吞掉 | 本程序的钩子根本没看到这个键，说明更上层有钩子把它吞了 |
| 不是全局热键 | 看到了，但引擎 A 里它不是已占用，说明只是当前窗口自己处理的键 |

**怎么用**：图形界面「钩子检测」页，填好组合键点「布防（安装钩子）」（**此刻才装钩子**），
立即按下该键，看结论。判定为「被吞掉」时，用右侧「对照排除」工作流逐条记录、人工退出可疑软件再对比。

**风险**：同样会安装钩子。本页**只观察、不吞键、不改键，也绝不结束或暂停任何进程**。

### 引擎 D —— 配置聚合（只读，不需要管理员）

**做什么**：解析已知软件的配置文件（PowerToys、Everything、OBS、NVIDIA ShadowPlay、
Wallpaper Engine、MSI Afterburner 等）里的热键声明，和引擎 A 的实测结果做 diff，产出「真相表」。

**怎么用**：跟着 `--scan` / 「开始扫描」一起自动运行，结果在「配置真相表」页和报告里。

**风险**：无。所有读取都是只读，损坏或缺失的配置文件会被跳过。

## 3. 为什么「扫描说空闲」也可能被占用

这是最容易误解的一点。引擎 A 只能看到通过 `RegisterHotKey` 注册的热键；有一大类热键**不经过它**：

- **键盘钩子型热键看不到。** PowerToys 键盘管理器、AutoHotkey、输入法、部分游戏工具用底层键盘钩子
  实现热键。它们不调用 `RegisterHotKey`，所以引擎 A 会把键位报成「空闲」——但实际按下后会被它们抢先处理。
- **只有当前会话可见。** `RegisterHotKey` 是会话级/窗口站级的，别的登录会话注册的热键这里探测不到。
- **「注册失败」不等于「软件占用」。** 少数组合会返回 1409 之外的错误码（系统保留或特殊限制），
  报告里会把错误码一并列出。

结论：引擎 A 说「空闲」只是「没有别人通过 RegisterHotKey 占了它」。要确认「按下去到底有没有人响应」，
请用引擎 B 监听、用引擎 C 判断是否被钩子吞掉。

## 4. 用引擎 B 找出「按了没反应的键」

假设某个键按下去没反应，你想知道是被谁处理了：

1. 打开「按键归属」页（或 `--listen`），点「开始监听」。
2. 按下那个键，观察是否出现归属记录。
3. 分两种情形：
   - **出现记录**：记录里写明是哪个进程持有了它。就是那个软件把它抢走了。
   - **没有记录**：说明它要么不是全局热键（只是当前窗口自己处理的键），要么被更上层的钩子吞掉了。
     这时用引擎 C（「钩子检测」页）进一步判断。

小技巧：把 `--listen` 和引擎 C 的对照排除工作流配合使用——先记录「现在」的结论，退出一个可疑软件，
再测一次，对比两次结果就能定位到责任软件。

## 5. 权限与完整性说明

- **管理员（UAC）**：非管理员运行时，看不到「以管理员身份运行的进程」的热键归属（例如 PowerToys）。
  界面顶部提示条和「扫描总览」页都有「以管理员身份重启」按钮；命令行可用 `--elevate` 提权重启
  （会保留原命令行参数）。用户在 UAC 里点「否」时程序会识别为「已取消」并正常返回，不会报错崩溃。
- **低完整性（Low IL）**：如果 exe 位于带 `Mandatory Label\Low` 标签的目录（例如某些同步盘工作区），
  进程会以低完整性运行。后果：写 `%TEMP%`、`%LOCALAPPDATA%` 会被拒绝；**UIPI 会拦住钩子注入**，
  引擎 B/C 基本失效。**请把 exe 复制到普通目录（如 `C:\Tools\`）后再运行。**
- **UIPI（用户界面特权隔离）**：低完整性或非提权进程无法向更高完整性进程注入钩子，这是 Windows 的
  安全机制，不是本工具的 bug。

---

## 6. 已知限制

- **看不到 32 位进程**：本程序是 64 位，注入的 hook DLL 也是 x64，覆盖不到正在运行的 32 位进程的归属。
- **钩子型热键不走 WM_HOTKEY**：用键盘钩子实现的热键（键盘管理器、输入法、AutoHotkey）不会出现在
  引擎 A 的占用表里，也不会触发引擎 B 的归属报告。
- **只覆盖当前会话**：别的登录会话的热键看不到。
- **部分配置编码未验证**：MSI Afterburner、Everything 的热键编码格式需要人工核对。
- **引擎 B/C 需要装钩子**：这是设计使然，且只在显式操作时发生。

## 7. 常见问题排查

**Q：扫描不到任何占用 / 数字明显偏小？**
A：确认没有同时运行另一个会大量注册热键的程序；换到普通目录重跑（低完整性会影响写入与探测）。

**Q：「开始监听」报错或一个进程都看不到？**
A：多半是低完整性（把 exe 复制到普通目录）或非管理员（用「以管理员身份重启」/ `--elevate`）。

**Q：报告写不进去 / 提示拒绝访问？**
A：把输出路径改到可写目录（例如程序所在目录）。低完整性进程写不了 `%TEMP%`、`%LOCALAPPDATA%`。

**Q：某个键在引擎 A 里是空闲的，但按下去还是没反应？**
A：它很可能被钩子型热键占用了。用引擎 B 监听、引擎 C 判断。

**Q：怎么把界面切成英文？**
A：命令行加 `--lang en`，或在「报告与关于」页 / 帮助窗口里切换语言（切换后重启程序生效）。

## 8. 卸载 / 清理

HotkeyHound 是绿色单文件程序，**没有安装程序、不写注册表**：

- 直接删除 `HotkeyHound.exe` 即可。
- 程序会在 `%LOCALAPPDATA%\HotkeyHound\`（或 exe 同目录）下释放一个用于引擎 B 的原生 DLL
  （`HotkeyHound.Hook.dll`）以及 `settings.ini`。删除该目录即可。
- 引擎 B 的 DLL 会被注入到当前会话的进程里；这些注入**在进程重启后自然消失**，
  **重启电脑可彻底清除**。停止监听时本程序也会调用 `UnhookWindowsHookEx` 卸载钩子。
